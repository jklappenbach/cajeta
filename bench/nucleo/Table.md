# Table

`cajeta.nucleo.frame.Table` — the lazy, typed dataframe whose operations are built then run. The groupby and join rows are the h2oai db-benchmark questions at 1e6 rows, with 1e7 as a variant on machines with the memory for it.

## Benchmarks

| id | workload | against | check |
|---|---|---|---|
| `nucleo/table-groupby` | db-benchmark groupby q1 to q5; variants q1..q5 × {1e6, 1e7} | pandas, polars, DuckDB | aggregate checksums against DuckDB |
| `nucleo/table-join` | db-benchmark join: small, medium and big right tables; variants × {1e6, 1e7} | pandas, polars, DuckDB | row count and checksum |
| `nucleo/table-sort` | sort 1e7 rows by two keys | pandas, polars, DuckDB | ordered |
| `nucleo/table-filter` | filter 1e7 rows on a predicate selecting 10% | pandas, polars, DuckDB | row count |

The tables are generated by the db-benchmark generator with a recorded seed, so every competitor reads identical data.

## Reproduce

```sh
cd bench
./bench.sh --bench table-groupby               # Cajeta
./bench.sh --bench table-groupby --competitors # every pinned competitor
```

Every row records the compiler and competitor versions, flags, machine, OS and driver; [METHODOLOGY](../METHODOLOGY.md) states the rules a number must satisfy before it is published.
