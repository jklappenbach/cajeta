# Release regression subset — the curated set of gtest suites run by the
# release workflow (instead of the full ~1725-test battery) on every
# cross-compiled target.
#
# RATIONALE
# ---------
# The front-end (lexer / parser / typer / borrow-checker) is host-
# independent: if a suite passes on the primary x86_64-linux build it
# passes on every target, because nothing in it is target-conditional.
# Those suites (JSON synth, lambdas, template wildcards, annotations,
# aspects/DI, multiclassing, getters/setters, ...) are validated by the
# full local suite and are intentionally NOT here.
#
# This file lists only what the LLVM back-end + C runtime lower
# DIFFERENTLY per ISA / OS / endianness / ABI — i.e. where a cross-built
# binary can break even though the front-end is green everywhere — plus a
# thin end-to-end codegen/dispatch smoke that proves a compiled program
# actually runs on the host.
#
# FORMAT
# ------
# One gtest filter pattern per line (`Suite.*` matches a whole suite).
# Blank lines and `#` comments are ignored. Consumers (release_tests.sh,
# release_tests.cmd, and the CMake `release_tests` target) join the
# patterns with `:` into a single --gtest_filter.
#
# An `optional:` prefix marks a FEATURE-GATED suite: one whose tests are
# compiled out when the feature's dependency is absent on the build host
# (so zero matches there is expected, not drift). release_tests.sh skips
# an absent optional suite with a loud warning and still runs it wherever
# it exists; a missing NON-optional suite remains a hard error.
#
# MAINTENANCE
# -----------
# release_tests.sh fails loudly if any pattern below matches zero
# discovered tests (a suite was renamed or removed) — so this list can't
# silently rot into a no-op. When a suite is renamed, fix the line here.
