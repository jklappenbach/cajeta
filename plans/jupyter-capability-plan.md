# Cajeta → Jupyter: Implementation Plan

## Overview

This plan makes the cajeta compiler Jupyter-notebook capable by adding a `cajeta kernel` subcommand that wraps three load-bearing pillars over the existing LLVM ORC JIT path. **Pillar one** turns today's single-shot `CajetaJit` (which builds one `LLJIT`, adds one merged module, and destroys the JITDylib on `~CajetaJit`, `test/jit/JitTestHelper.cpp:99-118,384-440`) into a long-lived session that owns one `LLJIT`, one accumulating `JITDylib`, and a single never-unloaded bootstrap module that holds the embedded runtime bitcode. **Pillar two** desugars free-form cell text (a sequence of `blockStatement`s, `CajetaParser.g4:520-528`) into the valid `compilationUnit` Cajeta's grammar requires (`CajetaParser.g4:36-39`), wrapping statement bodies in a synthetic class+method, lifting `var` bindings for cross-cell visibility, and capturing trailing expressions for display. **Pillar three** makes the per-method ownership/move/borrow analysis (`Scope` objects allocated per `Method::createScope()`, freed at `destroyScope()`, `Method.cpp:1465,1468`) and the scope-exit drop discipline (`__cajeta_drop_push`/`__cajeta_drop_pop_run`) span cells via a SESSION-scoped binding registry that outlives any single compile. The kernel wrapper speaks Jupyter v5.3 over ZeroMQ, runs cells off the poll-loop thread for streaming and interrupt, and routes captured stdout/stderr, structured exceptions, and rendered results into iopub. **The entire plan rests on one architecture decision (Section 1): a single long-lived `Compiler` owning one `llvm::LLVMContext`, into which each cell's `llvm::Module` is created and added via `addIRModule`, eliminating the per-cell `Linker::linkModules` merge — this decision is authored first (M0) and is an input to, not a summary of, every later section.**

## Milestone Sequencing

The ladder is dependency-correct: an architecture-decision gate precedes all code, and each milestone names the sections that feed it. Crucially, M2 cannot begin until the M0 context/linker decision and the cross-cutting decision register (Section 9) are committed, because Sections 1–3 must already obey those choices.

- **M0 — Architecture & Decision Register (Sections 1, 9).** Resolve and commit the load-bearing decisions BEFORE any implementation: (1) one long-lived `Compiler`/`LLVMContext`, per-cell `llvm::Module` created in that shared context and added via `addIRModule` — no `Linker::linkModules` across cells; (2) global ctors run per-new-module only, never re-`initialize()` the whole dylib; (3) `__cajeta_task_shutdown` deferred to session shutdown; (4) one `CajetaSession` per process (process-global `canonicalMap`/`strutureToModule` forbid >1 session per process); (5) cells run on a dedicated execution thread off the ZMQ poll loop; (6) recoverable-throws-only error recovery for v1; (7) OpenSSL (already linked) for HMAC, not libsodium. Output: `cajeta-docs/Notebooks.md` decision table. This is a true prerequisite gate, not a deliverable of a later milestone.

- **M1 — Single-cell kernel over real ZMQ (Sections 5, 6, 4).** Reuse the existing single-shot compile front-half but route it through the new `CajetaSession::addCell` seam and the kernel transport. A self-contained cell compiles, runs, and streams stdout via the `ScopedFdCapture` harness, with `kernel_info`/`execute` handshake, execution counter, and `parent_header` correlation. Feeds on Section 5 (transport), Section 6 (CLI/build/session seam), Section 4 (fd capture).

- **M2 — Persistent session JIT (Sections 1, 2, 6).** Layer in the long-lived `LLJIT`/`JITDylib`, the bootstrap-vs-per-cell module split, resource-tracker shadowing, per-cell `initialize` gating, and shared stdlib/template instantiation. Cell K resolves symbols defined in cells <K; redefinition is last-write-wins. Requires M0's context/linker decision. Feeds on Section 1 (JIT substrate), Section 2 (desugaring), Section 6 (session API).

- **M3 — Session-spanning ownership & drop (Sections 2, 3).** Add the `SessionOwnershipTable` (cross-cell move/borrow), the session-binding read/write codegen contract (identifier → `__cajeta_session_binding_get`, owners bypass the function-local drop chain), the string-keyed runtime registry, and drop-on-redefinition/drop-all-on-reset. Depends on M2's bootstrap-owns-runtime invariant and Section 2's lifting. Feeds on Section 2 (var-lifting/redefinition) and Section 3 (runtime registry, scope seeding).

- **M4 — Rich display, interrupt, is_complete (Sections 4, 5, 6).** Add `@ToString`/JSON result rendering with a non-compile-gating fallback, structured tracebacks via the new `__cajeta_get_trace` export, recoverable-throw interception, interrupt (poll-flag injection + thread architecture), and `is_complete_request` over the Section 2 classifier. Feeds on Section 4 (display/error), Section 5 (control channel, interrupt thread model), Section 6 (regression-filter wiring).

## 1. Architecture Decision: Persistent JIT Session, Context & Stdlib Sharing

Today every cell would get a fresh `CajetaJit` (`test/jit/JitTestHelper.cpp:140`) that calls `LLJITBuilder().create()`, `addIRModule`, `initialize(mainDylib)`, and on `~CajetaJit` invokes `__cajeta_task_shutdown` then destroys the whole LLJIT (`JitTestHelper.cpp:99-118`). This is single-shot: the JITDylib dies with the instance and no symbol from cell K-1 is visible to cell K. This section turns that into a long-lived session that owns one `LLJIT` and one accumulating `JITDylib` (the existing `getMainJITDylib()`).

**This section first resolves the architecture contradiction that the rest of the plan rests on.** The chosen architecture (decision A): the session holds ONE long-lived `Compiler` owning ONE `llvm::LLVMContext` (`Compiler.h:87`), whose ctor `resetGlobals()` runs exactly once at session construction. Each cell's `llvm::Module` is created *in that shared context* and added to the persistent dylib via `addIRModule` as its own `ThreadSafeModule` wrapping the shared context. Because all cell modules share one `LLVMContext`, ORC can resolve cell K's extern declarations (emitted by `CajetaModule::ensureFunctionVisible`/`ensureFunctionInModule`, `CajetaModule.cpp:749-810`) against cell K-1's definitions already resident in the dylib — *without* the all-at-once `Linker::linkModules` consolidation at `JitTestHelper.cpp:273-281`. The "multi-source merge path" language from the recon is therefore explicitly retired for the kernel: cells are streamed via `addIRModule` into the shared-context dylib, not merged into a primary. (Decision B — keep `Linker` merges into a growing primary — is rejected because it forces re-adding a growing module per cell and re-running its ctors.)

The hard problems beyond context ownership are four. **(1) Symbol redefinition/shadowing**: ORC normally errors on a duplicate definition, so each cell module is added under its own `createResourceTracker()` and prior cells' clashing symbols are removed/overwritten (`ResourceTracker::remove` / re-define) so resolution is last-write-wins. **(2) Global-ctor hazards**: `LLJIT::initialize` runs `llvm.global_ctors` but is NOT safe to re-run blanket per cell. One-time ctors (the `emitUnrecoverableMarker` vtable registration at `Compiler.cpp:425-455` calling `__cajeta_set_unrecoverable_vtable`, plus runtime carrier/live-set init) are emitted only into the bootstrap module; per-cell ctors (per-class `generateStaticInitializers` clinit, XPU kernel registration) are gated to run only the ctors newly introduced by that cell, by adding each cell's module under its own tracker and calling `initialize` once after that tracker's `addIRModule`. **(3) Carrier-thread safety — and the real invariant the recon's `__cajeta_task_shutdown` comment (runtime:783-791) obscures**: that shutdown exists today because the carrier is bound to a *module's* statics that the JIT recycles between tests. In a persistent session the runtime statics live in ONE bootstrap module that is NEVER unloaded, so the carrier is safe to keep alive across cells *precisely because the bootstrap module owning the task/carrier statics outlives all cells*. The load-bearing constraint is therefore: **no cell module may ever re-emit or re-link the runtime bitcode** — exactly one definition of `__cajeta_task_shutdown` and one carrier must exist in the dylib, or the orphan bug the comment describes reappears. `__cajeta_task_shutdown` runs only on session teardown. **(4) Stdlib/template instantiation sharing**: every cell using `ArrayList<int32>`, `HashMap`, `String.format`, etc. triggers lazy template instantiation; without sharing, each cell re-instantiates the same specialization, exploding the dylib and producing duplicate definitions that last-write-wins would silently mis-resolve. The decision: a shared **instantiation cache** keyed by mangled specialization name, owned by the session. The bootstrap module emits the runtime + a fixed pre-instantiated set; novel specializations triggered by cell N are emitted into cell N's module, their mangled names recorded in the cache, and cells >N carry only externs to them (resolved via the shared dylib). A specialization is emitted at most once across the session.

## 2. Cell Semantics & Top-Level Desugaring

Cajeta's `compilationUnit` rule (`CajetaParser.g4:36-39`) admits only `packageDeclaration? importDeclaration* typeDeclaration*` — no top-level statements or expressions; the minimal runnable unit needs a package, a public class, and a method body. A notebook cell is a free sequence of `blockStatement`s (`CajetaParser.g4:520-528`). This section defines a deterministic desugarer that rewrites raw cell text into a valid `compilationUnit` before it reaches `CajetaLlvmVisitor::visitCompilationUnit` (`CajetaLlvmVisitor.h:40-49`). It classifies each cell into genuine top-level forms (package/import/type declarations, passed through) versus a "statement body" wrapped in a synthetic class `__cajeta.notebook.Cell$N` with a `public static int32 __cell$N()` entry method, given a collision-free FQN so the prescan archive (`ArchivePrescanVisitor`), `CajetaType::canonicalMap`, and `CajetaModule::strutureToModule` register it like any other type.

The hard semantics live in four transforms. **First, var-lifting**: a top-level `var`/typed local (`CajetaParser.g4:526-528`) must survive into later cells, but the per-method `Scope` is destroyed at `Method::destroyScope()` (`Method.cpp:1468`) and owned locals auto-drop at scope exit (`LocalVariableDeclaration.cpp emitDropEntryFor` → `__cajeta_drop_pop_run`). The desugarer lifts session-visible bindings into a session registry: statically it records `(name → declared type, ownership shape, defining cell, version)` so later cells parse against them; at codegen it emits the binding via the SESSION-scope drop path (Section 3) so the value is NOT dropped at `__cell$N()` return. **The read path is the core mechanic and is pinned in Section 3 deliverable 4, consumed here**: when the visitor resolves an identifier absent from the local `Scope` but present in the `SessionOwnershipTable`, codegen emits a `__cajeta_session_binding_get(name)` call returning the stored pointer, cast to the recorded static type, and registers NO local drop entry for it — it is a session-get, not an alloca-load. **Second, trailing-expression capture**: Cajeta has no implicit-return; a cell whose final `blockStatement` is a non-void `ExpressionStatement` (`Statement.h:60-76`) is rewritten so the value is captured for display — desugar `expr;` into `var __cell$N$result = expr;`, lift it, and hand its type+value to the renderer. **Ownership-bearing trailing expressions are first-class**: a trailing `#owner` (move) result registers as a SESSION owned binding (dropped on reset/redefine); a trailing borrow-returning call cannot outlive its owner and is either rejected for display or deep-rendered-then-dropped within the cell; void expressions, non-expression trailing statements, and empty cells capture no result. **Third, redefinition**: re-declaring `var x` shadows the prior binding (new ownership state, old session entry dropped, version bumped); redefining a class/method re-registers/versions the canonical name so the latest wins. **Fourth, type/aspect/DI cells**: genuine `typeDeclaration` cells compile as real types and bypass wrapping; `@Aspect`/`@Component`/`@Inject`/template-class cells are TYPE_DECL (they cannot be method-local), and `resolveAdviceMatches`/`resolveDependencyGraph` (which run per-`Compiler`, not incrementally) must be re-run incrementally against the accumulated archive after each such cell — or, for v1, aspect/DI definitions are restricted to first cells with that restriction documented.

Imports/packages are session-level: an `import x.y.Z;`-only cell mutates the session import set (via `CajetaModule::onImportDeclaration`) forward-only; a bare package declaration sets the notebook's single package.

## 3. Session-Spanning Ownership, Borrow & Live-Set

Cajeta's ownership analysis lives entirely in `Scope` objects (`Scope.h:46,50` — `movedNames`/`movedPaths`) allocated per-method via `Method::createScope()` (`Method.cpp:1465`) and freed at `destroyScope()` (`Method.cpp:1468`); move marks are written by `MoveExpression::generateCode()` (`Expression.cpp:1213` `markMoved`, `:1233` `markMovedPath`) and read at `IdentifierExpression`/`DotExpression` codegen. Because each cell compiles to one synthetic function (Section 2), all move/borrow state is discarded at that function's scope destruction. Symmetrically, the runtime drop discipline is scope-exit-only: owned locals push at declaration (`LocalVariableDeclaration::emitDropEntryFor`, LVD.cpp:65-99 → `__cajeta_drop_push`) and fire LIFO at block close (`Method::emitTopFrameDrops`, `Method.cpp:126-151` → `__cajeta_drop_pop_run`), so a cell-exported heap value would be freed at cell-function return.

The approach introduces a persistent `SessionOwnershipTable` (keyed by binding short-name) recording, per exported `var`, its declared static type, defining cell, `#`-transfer state, the cell where the move occurred, `redefVersion`, and `liveBorrows`. **Scope seeding model**: because move marks are recorded on the *declaring* scope and looked up by walking the parent chain (`Scope.cpp:41-77`), session-bound identifiers participate in move/borrow checks as **synthetic locals injected into the seeded method scope at entry** (with `declaredType` from the table), so `isMoved`/`isPathMoved`/`isNotYetAssigned`/`recordLiveBorrow` operate uniformly and treat a session-get identifier as a valid borrow source. Section 2's desugarer seeds each cell's synthetic-method scope from the table before codegen and writes back new moves/redefinitions after. On the runtime side, SESSION owners bypass `__cajeta_drop_push` and register into a new string-keyed registry. **The string-keyed registry ↔ pointer-keyed live-set ↔ per-fiber drop-chain reconciliation is specified as a concrete protocol** (deliverable 3), not asserted as a goal: the value is already in the live-set (added at malloc, cajeta_runtime.c:218/227); `__cajeta_session_binding_set` only records `{name→(obj,drop_fn)}`; `__cajeta_session_binding_drop`/`drop_all` invoke the `drop_fn`, which itself performs `__cajeta_live_set_claim`+free exactly as `__cajeta_drop_pop_run`'s `drop_fn` does. SESSION owners must NOT also hold a function-local drop entry (else double-free). This keeps the function-scope drop chain structurally unchanged.

## 4. Runtime, Output Capture & Rich Display

This section makes a cell's execution observable: capturing stdout/stderr from JIT'd code, routing runtime exceptions and compile diagnostics into structured Jupyter error output, and rendering the result value into a MIME bundle. The runtime has no in-process interception — every print funnels through `__cajeta_emit(int32_t stream, const char* s, size_t n)` → POSIX `write(stream, s, n)`, unbuffered (cajeta_runtime.c:2199-2215). The proven observation mechanism is the test harness's `captureFd` idiom (`test/expression/SystemIoTests.cpp:42-66`): `dup()` the real fd, `dup2()` a temp-file fd over it, run, restore, read. The kernel hardens this into a `ScopedFdCapture` over fds 1 and 2. **Crucially, incremental draining requires concurrency**: cells run on a dedicated execution thread (Section 5), and a draining reactor reads the capture temp-files *while* the cell runs, forwarding partial output to iopub `stream` messages. Without that thread split, only a single post-`run()` drain is possible — so the incremental requirement is owned by the Section 5 thread architecture and consumed here.

Error routing has two sources. Runtime throws are handled by `__cajeta_emit_uncaught` (cajeta_runtime.c:2107-2148), which walks the `Throwable { vtable@0, String message@8 }` / `String { bytes@8, byteLength@16 }` layout and calls `__cajeta_print_trace(value, 2)` — but that only writes `backtrace_symbols` text; there is no structured retrieval (`__cajeta_get_trace` is named in a comment at cajeta_runtime.c:1987 but never defined). **A v1 boundary is explicit**: only RECOVERABLE throws become `error` replies; UNRECOVERABLE throws `abort()` in the runtime (`__cajeta_is_unrecoverable` → abort, cajeta_runtime.c:1892-1925) *before* any setjmp catch frame can run, so they require a kernel-supervisor restart unless the optional kernel-mode runtime hook (deliverable 7) is built. Compile diagnostics flow through `CajetaLogger::log` to glog with Levenshtein hints from `Diagnostics.{h,cpp}`. The result-display path leverages `@ToString` (`SynthesizedToStringMethod.h`: PROPERTIES and JSON) but **never gates cell compilation on displayability**: because `@ToString` array/interface fields and the Tier-1 `JsonSynthesizer` arrays/Optional limits are *compile* errors, the formatter must call `toString` only when the static type already has one and otherwise emit a `ClassName@<hex>` fallback at display time — trailing capture never auto-synthesizes `@ToString`.

## 5. Jupyter Protocol Kernel, Transport & Execution-Thread Model

This section builds the kernel process speaking Jupyter v5.3 over ZeroMQ and bridges it to the session substrate. The reconnaissance confirms a green field: a grep across `src/` for `zmq`, `kernel_info`, `execute_request` yields zero hits, and `src/main.cpp:145-381` is a positional-arg batch dispatcher (`archive` at line 152). We add a `cajeta kernel` subcommand plus a self-contained transport layer: connection-file parsing (ip/transport/ports/key/scheme), five ZeroMQ sockets (shell ROUTER, control ROUTER, stdin ROUTER, iopub PUB, heartbeat REP), a `zmq_poll`-driven event loop, HMAC-SHA256 signing/verification, and multipart framing (`<ids> <DELIM> <hmac> header parent_header metadata content`). **HMAC uses OpenSSL's HMAC/EVP_MAC** — OpenSSL (`OpenSSL::Crypto`) is already a required dependency linked into `cajeta_lib` (CMakeLists.txt:29,507) for archive signing; libsodium is NOT added.

**The thread architecture is a load-bearing deliverable of this section**, owned here and consumed by Sections 4 and 6: the ZMQ poll loop runs on the main thread; each cell executes on a *dedicated execution thread*; a draining reactor forwards captured output during execution. This split is what makes incremental output drain (Section 4), control-channel `interrupt_request` servicing while a cell runs, and heartbeat liveness all simultaneously possible — running the cell inline in the shell handler would starve all three.

The handler set covers v1-minimal: `kernel_info_request`→`kernel_info_reply` (protocol "5.3", language "cajeta", extension ".cajeta"), `execute_request`/`execute_reply` with a monotonic counter, `is_complete_request` driven by the Section 2 `CellClassifier` + a parse of the appropriate rule (`blockStatement*` for statement bodies, `compilationUnit` for type-decl cells — never a bare `compilationUnit` parse of statement text, which would wrongly reject every statement cell), `interrupt_request`/`shutdown_request` on control, and iopub `status`/`stream`/`execute_result`/`display_data`/`error`. Every iopub/reply carries the request's header as `parent_header`. **Interrupt is a designed mechanism, not just a flag name**: the runtime exposes a session interrupt flag, codegen injects a poll of that flag at loop back-edges (and the cell-entry harness checks it), so a spinning cell observes the interrupt; the documented v1 limitation is that tight non-allocating FFI/external calls and JIT codegen itself are not interruptible (graceful degradation).

This section is the delivery spine sequencing Sections 1-5 into a shippable `cajeta kernel` subcommand and defining build, CLI, test-harness, and docs machinery. The CLI follows the `dispatchArchive` precedent: `main.cpp:151` already branches on `argv[1]=="archive"` before constructing `Compiler`, and `ArchiveCommands.cpp:1262` `dispatchArchive` does string-dispatch returning POSIX codes; `cajeta kernel` is a sibling branch routing to `cajeta::dispatchKernel(argc, argv)` in `src/cajeta/cli/KernelCommands.{h,cpp}`, with `kernel run <connection-file>` (event loop) and `kernel install [--user|--system]` (writes `kernel.json` with `"argv":["cajeta","kernel","run","{connection_file}"]` to `~/.local/share/jupyter/kernels/cajeta/`). REQUIRED)`/IMPORTED-target-with-fallback pattern already used for glog, GTest, OpenSSL, zstd, LLVM (lines 50-78), linking into `cajeta_lib` (line 492) so both the `cajeta` exe (line 532) and `cajeta_test` (test/CMakeLists.txt:22) use the session/kernel code. **No libsodium** — HMAC reuses the already-linked `OpenSSL::Crypto` (CMakeLists.txt:29,507). ## 7. Cross-Cutting Risks & Open Decisions

These risks span sections; each names the load-bearing constraint and where it is resolved.

1. [ ] **Architecture: one `LLVMContext`, per-cell `addIRModule`, no `Linker` (RESOLVED, decision A).** The plan's foundational choice — committed at M0 (Section 1, Section 9 register row 1). Section 1 retires the "multi-source merge path"; cells share the long-lived `Compiler`'s context so ORC resolves cross-module externs without `Linker::linkModules`. Every milestone gate after M1 verifies this.

2. [ ] **Process-global type state forbids >1 session per process (RESOLVED).** `canonicalMap`/`strutureToModule` are process-global statics cleared by `resetGlobals()` in the `Compiler` ctor (`Compiler.h:217-220`). One long-lived `Compiler` fixes per-cell reset but makes two `CajetaSession`s in one process corrupt the maps. Decision: one session per process; kernel tests run in separate processes (Section 6 deliverable 4, test `KernelIsolationProcessPerSession`). Alternative deliverable: de-globalize the maps into `Compiler`-instance state (deferred to v2 unless required).

3. [ ] **Structured concurrency: the hazard is `detach`, not `spawn` (RESOLVED).** `spawn` is legal only inside `scope{}`, and `__cajeta_scope_exit` JOINS all spawned tasks at the cell's closing brace (runtime:578-600), so a spawned task cannot outlive its cell — the carrier-orphan-across-cells scenarios are not reachable via normal structured concurrency. The real cross-cell-lifetime hazard is `detach` (grammar:763); Section 3 test 9 rebases on it. Combined with the deferred-`__cajeta_task_shutdown` decision, the only teardown that matters is SESSION shutdown.

4. [ ] **Execution-thread / poll-loop concurrency (RESOLVED, owned by Section 5).** Cells run on a dedicated execution thread; the poll loop and a draining reactor run on the main thread. This single architecture makes incremental output drain (Section 4), control-channel interrupt servicing, and heartbeat liveness all simultaneously achievable; running inline in the shell handler would starve all three.

5. [ ] **Session-registry ↔ live-set ↔ drop-chain protocol (RESOLVED, Section 3 deliverable 3).** Specified as a concrete claim/free protocol: `set` only records `{name→(obj,drop_fn)}`; `drop`/`drop_all` invoke `drop_fn`, which does `__cajeta_live_set_claim`+free exactly as `__cajeta_drop_pop_run`; SESSION owners carry no function-local drop entry. Verified under `drop_chain_validate(1)` + `poisonFree(1)` (test `SessionBindingClaimedExactlyOnce`).

6. [ ] **Cross-cell session-binding read codegen (RESOLVED, pinned in Section 3 deliverable 4).** An identifier resolved to a session binding emits `__cajeta_session_binding_get(name)` cast to the recorded static type with no local drop entry. Pinned once in Section 3 and consumed by Section 2 to break the circular hand-off.

7. [ ] **Stdlib/template instantiation sharing (RESOLVED, Section 1 deliverable 4).** A session instantiation cache keyed by mangled specialization name guarantees each specialization is defined once; novel specializations are emitted into the first cell that uses them and referenced via externs thereafter — preventing dylib explosion and last-write-wins mis-resolution of duplicated template symbols.

8. [ ] **Unrecoverable exceptions abort the kernel (BOUNDARY DECISION, Section 4 deliverable 5).** `__cajeta_is_unrecoverable` → `abort()` (cajeta_runtime.c:1892-1925) runs before any setjmp catch frame. v1 ships EITHER a kernel-supervisor restart (default) OR an optional `__cajeta_set_kernel_mode` longjmp hook; only recoverable throws become `error` replies. The choice is recorded in the register; Section 4/5 acceptance criteria are scoped accordingly.

9. [ ] **Displayability must never gate cell compilation (RESOLVED, Section 4 deliverable 7).** `@ToString`/JSON synthesis failures (arrays/interfaces/nested Optional) are compile errors; the formatter therefore calls an existing `toString` if present and otherwise emits a `ClassName@<hex>` fallback at display time — trailing capture never auto-synthesizes `@ToString`. A non-displayable trailing result still executes (test `NonDisplayableResultStillExecutes`).

10. [ ] **`is_complete` must parse the right rule (RESOLVED, Section 5).** A bare `compilationUnit` parse rejects every statement-body cell (grammar:36-39). `is_complete` runs the Section 2 `CellClassifier` then parses `blockStatement*` (statement bodies) or `compilationUnit` (type-decl cells).

11. [ ] **Lazy/eager verifiability (RESOLVED, Section 1 test 10).** The compiler's eager Phase 1/2 quiescence compiles referenced methods before IR reaches the JIT, so the policy flag controls only ORC *materialization* timing of an already-valid module; the test's undefined symbol is legal IR so the difference is observable only at materialization.

12. [ ] **Dependency surface (RESOLVED).** HMAC reuses the already-linked `OpenSSL::Crypto` (CMakeLists.txt:29,507); libsodium is not added. Only libzmq/cppzmq + a JSON lib are genuinely new (Section 5/6).

13. [ ] **Open / deferred to v2.** Unbounded memory growth from accumulated shadowed cell modules (ORC has no partial unload — only full session reset reclaims); GPU/`@Kernel` lazy compilation per cell; `stdin`/`input()` round-trips; `complete`/`inspect` code-assist; multi-session isolation via de-globalized type maps; Windows `backtrace` (DbgHelp) for traceback parity. Each is named in the register with the section it would attach to, and none blocks the M1-M4 v1 path.
